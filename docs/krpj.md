# Kratience Project Format (KRPJ)
A Kratience project is a `.krpj` file: a zip archive holding `game.json` at its root plus the project's own assets at their `./` paths. The editor saves and opens `.krpj` files, gm2kr exports them, and Kressel (krplayer) plays them.

```
coin-collector.krpj
├── game.json            main project file (text/json, described below)
├── sprites/<key>/<frame>.png
├── fonts/<key>.png
├── tilesets/<key>.png
├── sounds/<key>.ogg|wav  (gm2kr; any audio path works)
└── files/<path>          included files (gm2kr)
```

`game.json` is generated by the editor and interpreted by the engine. The editor works somewhat like Scratch/TurboWarp does, and the (interpreted) scripting blocks in `game.json` reflect the codeblocks as they appear in the editor.

All non-text resources are external files not in `game.json`, either as assets in the project (./asset.ext, stored next to `game.json` in the `.krpj` or on the CDN) or shared assets (/sa/~someone/asset.ext). (e.g. images, audio)

This is to allow expensive per-room assets to be loaded in during room transitions, among other advancements.

`game.json` is not a one-to-one data.win-to-JSON representation, it is its own format built to be interpreted in a web player. Where the ease & speed of the Kratience engine & editor benefits, changes will be made from GameMaker's setup (for example, the use of individual textures over texture maps).

## Example Small Project Structure (game.json)

        "title": "Coin Collector",
        "author": "admin",
        "revision": 1,
        "date_created": 1793770552, // timestamp(z)
        "date_updated": 1793770552,
    },
    "cfg_gm_compat": {
        "imported_from": null,
        // if imported from a gamemaker project, has some info about the origin
    },
    "cfg_defaults": { // can be changed via game scripting
        "width": "default",
        "height": "default",
        "fps": 60,
        "window_title": "Coin Collector",
    },

  "sounds": {

Roughly equivalent GML for `obj_player`'s step event:
```gml
if (keyboard_check(vk_right)) x = x + move_speed;

```

## Field reference
Fields beyond the example above. All are optional unless noted; the types live in `krplayer/src/krpj.ts`.

* `cfg_gm_compat.imported_from`: `null`, or `{ "tool": "gm2kr", "game": <GM project name>, "bytecode": <15-17>, "gm_version": [major, minor, release, build] }`.
* `cfg_defaults.width` / `height`: `"default"` means the size of `init_room`.
* `room_order`: room keys in game order (`room_goto_next` etc.). Defaults to the key order of `rooms`.
* Asset keys (`sprites`, `fonts`, `objects`, `rooms`, `sounds`, `tilesets`, `paths`, `shaders`...) share one namespace, since `["_as", name]` names any of them. gm2kr uses the GameMaker asset names as keys, in GameMaker's order, so an asset's index within its kind is GM's index (imported code that uses raw asset numbers keeps working).
* `global_init`: scripts (bare or placed, see Script layout) run once at game start, in order, before the first room, with `self` = the global scope (GameMaker 2.3+ script files' top-level code, which also defines their functions as global variables).
* `scripts`: script asset index → function key (or `null`), for code that names scripts by number (`script_execute(n)`, `asset_get_index`). A function reference (`["_fn", key]`) evaluates to its script index when it has one, and to a method otherwise.
* `audio_groups`: audio group names by index (`sounds[k].group` indexes it).
* `included_files`: path the game opens, relative to its working directory (`"lang/lang_en.json"`) → asset path (`"./files/lang/lang_en.json"`). Non-audio files are read up front (GML file functions are synchronous); audio is streamed when the game asks for it (`audio_create_stream`).

**Functions** (`functions`): `args` are named parameters (locals initialised from the arguments; imports have none and use `argument0`... instead), `argc` the argument count GameMaker declared, `ctor` true for constructors (`fnc_new`). `x`/`y` place the body on the editor canvas and `loose` holds placed stacks lying on it (see Script layout).

**Script layout**: each entry of an object's or room's `scripts` and of `global_init` is either a bare script (a hat for objects/rooms, a block list for `global_init`) or a placed one, `{ "x": 24, "y": 24, "script": <the same>, "loose": true }`. `x`/`y` are the canvas position in editor pixels (`null` or missing = auto-placed). Entries that never run, so a half-built canvas still loads:
* `"loose": true` (any list), or every entry of a function's `loose`.
* In object/room `scripts`: an entry without a hat (a block list, or `[]`), or a hat with no block list after it (`["evt_step"]`).

A hat with an empty block list (`["evt_step", []]`) is a real, empty event: like an empty event in GameMaker, it overrides the parent's. Imports only have bare scripts. (krpj 0.1 kept positions in a top-level `editor` field; kreditor moves them onto the scripts when it opens such a file.)

**Sprites**
* `speed`: frames per second; with `"speed_type": "frame"`, frames per game frame instead.
* `bbox`: collision box `[left, top, right, bottom]` in inclusive image pixels. Defaults to the whole image.
* `mask`: `"rect"` (default; collides as the axis-aligned box around the scaled/rotated box), `"rotated"` (the rotated box itself) or `"precise"` (per-pixel, using `mask_bits`; without it, treated as `"rotated"`).
* `mask_bits`: precise masks only. A file of one mask, or one per frame (picked by `floor(image_index)`), each `ceil(width / 8)` bytes per row for `height` rows; the high bit of each byte is the leftmost pixel. Pixels outside `bbox` never collide.
* Frames are full, untrimmed images; `origin` is relative to their top-left.

**Sounds**: `src` (`""` for a sound with no audio data, which plays nothing), `volume`, `stream` (decoded on first use rather than at load), `pitch` (default 1), `group` (default 0).

**Fonts**: `size`, `bold`, `italic`, `antialias`, `line_height`, `ranges` and `glyphs` (`"code": [x, y, w, h, shift, offset]` in the atlas) as in the example; `kerning` is optional.

**Paths** (`paths`): `points` is a list of `[x, y, speed]` (speed is a percentage of the path speed, 100 = normal); `smooth` (curved instead of straight segments), `closed` (the last point joins the first) and `precision` (curve subdivision, 1-8, default 4) are optional. Like other assets, a path's index within `paths` is its id.

**Shaders** (`shaders`): `vertex` and `fragment` are GLSL ES 1.00 sources written for GameMaker's conventions: attributes `in_Position`, `in_Colour`, `in_TextureCoord`; uniforms `gm_BaseTexture` and `gm_Matrices[5]` (index 4 is world-view-projection). gm2kr keeps GameMaker's own prelude in the source.

**Tile sets** (`tilesets`): `image` is cut into a grid of `tile_w` × `tile_h` tiles, each padded by `border_x` / `border_y` on every side, `columns` per row. Animated sets add `frames`, `frame_time` (microseconds) and `ids` (tile → its frames' source tiles, `tile_count * frames` entries).

**Objects**
* `solid` (default `false`), `mask`: sprite key of a collision mask that differs from `sprite`, `depth`: the object's default depth.
* `scripts`: event hats (see krpj_opcodes.md), bare or placed (see Script layout). An object without an event uses its parent's.

**Rooms**
* `persistent` (default `false`), `speed` (GMS1-style room speed; 0 = use `cfg_defaults.fps`).
* `colour` (BGR) and `show_colour`: what the room is cleared to before drawing.
* `views_enabled` and `views` (up to 8): `view` `[x, y, w, h]` (the world rectangle), `port` `[x, y, w, h]` (where it's drawn), `border` and `speed` (following), `follow` (object key), `visible`.
* `scripts`: only `evt_create` (room creation code), run after every instance's create event and creation code.
* Layers: `visible` (default `true`), `x`, `y`, `hspeed`, `vspeed` (scrolling) and `id` (GM layer id, imports) on every layer.
  * `background`: `sprite` (or `null` for a plain `color`), `htiled`, `vtiled`, `stretch`, `foreground`, `alpha`, `image_index`, `image_speed`; `color` is BGR.
  * `instances`: `instances`, each with `object`, `x`, `y`, plus optional `scale_x`, `scale_y`, `angle`, `colour` (BGR), `alpha`, `image_index`, `image_speed`, `creation` (a script run right after that instance's create event) and `id` (the GM instance id, which code may refer to).
  * `assets`: `tiles` (GMS1-style tiles: `[x, y, sprite, left, top, width, height, scale_x, scale_y, colour]` with colour ABGR) and `sprites` (`sprite`, `x`, `y`, optional `scale_x`, `scale_y`, `angle`, `colour`, `alpha`, `image_index`, `image_speed`, `name`).
  * `tiles`: `tileset` (`null`: no tile set, draws nothing), `cols`, `rows` and `data` (rows × cols tile indices; 0 is empty, bits 28-30 mirror/flip/rotate).
* `instance_order`: instance ids in creation order (imports keep GameMaker's); without it, instances are created layer by layer, in list order.
* Every instance of the room exists (position, sprite and other built-ins set) before the first create event runs. Then, in creation order, each runs its create event, then its creation code. So a create event can read another room instance's `x`, but not variables that instance's own create event sets.

## Loading projects
krplayer takes a project as a `.krpj` archive (opened by the user, or fetched from a URL), as an unpacked `game.json` URL whose `./` assets sit next to it (e.g. on the CDN), or as the same set of files handed over in memory by gm2kr (see architecture.md). A URL is treated as a `.krpj` when its content starts with the zip signature `PK`, otherwise as `game.json`.
